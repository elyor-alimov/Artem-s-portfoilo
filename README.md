# Artem Yugay — интерактивное маркетинговое портфолио

Англоязычный сайт Артёма Югая: маркетинг, управление брендами и реализация комплексных проектов. Главная страница, шесть отдельных кейсов, About, контакты и скачиваемое резюме. Дизайн: Dark Editorial × Bold Creative — почти чёрный фон, крупная типографика Anton, акцентный фиолетовый, реальные материалы проектов и адаптивные композиции.

Это статический frontend: серверная часть, платные API, ключи и внешние сервисы не нужны. Публикация на GitHub Pages бесплатна в рамках условий GitHub. Данные не отправляются в аналитику. Шрифты поставляются вместе со сборкой, без обращения к Google Fonts.

## 1. Технологии и страницы

React 19, TypeScript, Vite, Tailwind CSS 4, GSAP + ScrollTrigger, React Router, Lucide. Цвета, размеры и композиции находятся в `src/styles.css`; Tailwind подключён через Vite и доступен для дополнительных утилит.

| Страница | Адрес после публикации |
|---|---|
| Главная | `/#/` |
| BYD / Megawatt | `/#/work/byd` |
| BARS / TATNEFT | `/#/work/bars` |
| Milliy App / NBU | `/#/work/milliy` |
| Asaka Bank | `/#/work/asaka` |
| Chevrolet / UzAuto | `/#/work/chevrolet` |
| PUBG Mobile | `/#/work/pubg` |
| Об Артёме | `/#/about` |

Для репозитория к адресу добавляется имя папки: `https://username.github.io/repository-name/#/work/byd`. Символ `#` обязателен: GitHub Pages отдаёт один `index.html`, а React Router выбирает страницу в браузере. Благодаря этому обновление страницы и прямая ссылка на кейс работают без серверных правил и копирования `404.html`.

Анимации собраны в `src/motion.ts`: короткий вход заголовков и портрета, появления при прокрутке, параллакс материалов кейса, индикатор прогресса. Наведение на проекты добавляет движение и увеличение изображения. Для системного параметра «Уменьшить движение» эффекты отключаются. Аккордеон компетенций работает с клавиатуры и касанием. Нативная прокрутка не подменяется.

## 2. Что установлено и что потребуется

1. Установите **Node.js 22 LTS** с https://nodejs.org/ (подходит и Node.js 24). npm устанавливается вместе с ним. Перезапустите терминал после установки.
2. Установите **VS Code** с https://code.visualstudio.com/.
3. Для отправки изменений установите **Git** с https://git-scm.com/downloads. На Windows можно пользоваться Git Bash или терминалом VS Code.
4. Проверьте в терминале:

```bash
node --version
npm --version
git --version
```

Команды должны вывести номера версий. Терминал — окно для выполнения команд, а не строка адреса браузера. Не вставляйте символы приглашения терминала перед командами.

## 3. Как запустить локально

Если проект уже скачан, откройте его папку в VS Code: **File → Open Folder**. Важно выбрать папку, содержащую `package.json`, а не родительскую папку. Затем **Terminal → New Terminal**.

Если скачиваете из GitHub:

```bash
git clone https://github.com/YOUR_USERNAME/YOUR_REPOSITORY.git
cd YOUR_REPOSITORY
```

Замените `YOUR_USERNAME` и `YOUR_REPOSITORY` своими значениями. Далее:

```bash
npm install
npm run dev
```

Откройте адрес, который выведет Vite (обычно `http://localhost:5173`). Для остановки нажмите **Ctrl+C** в терминале. При повторном запуске достаточно `npm run dev`. Для строго воспроизводимой установки по сохранённому `package-lock.json` используйте `npm ci` вместо `npm install`.

Проверка перед публикацией:

```bash
npm run build
npm run preview
```

Сборка проверит TypeScript и создаст `dist/`. Preview покажет именно production-версию. Не редактируйте `dist/`: следующая сборка её перезапишет.

## 5. Как заменить фотографии

Все пути задаются в `src/data/content.ts`. Функция `media()` создаёт стандартные пути для обложки, hero и галереи каждого проекта. В путях **нет** префикса `public/`: содержимое `public` оказывается в корне опубликованного сайта.

Пример для BYD:

1. Откройте папку проекта в VS Code.
2. В проводнике откройте `public/media/projects/byd/`.
3. Подготовьте оригинальную фотографию в WebP, например шириной 1920 пикселей. Не увеличивайте маленькое изображение искусственно.
4. Замените файл `cover.webp`. Сохраните регистр букв и настоящее расширение. Переименование JPEG в `.webp` не конвертирует формат.
5. Если имя осталось тем же, код менять не нужно. При новом имени измените `cover` у проекта (пример ниже).
6. Аналогично замените `hero.webp` и файлы галереи.
7. Сохраните, обновите браузер и проверьте домашнюю страницу и кейс на широком и узком экране.
8. Перед публикацией выполните `npm run build` и посмотрите `npm run preview`.

Та же последовательность применяется к папкам `bars`, `milliy`, `asaka`, `chevrolet`, `pubg`. Чтобы использовать нестандартное имя, добавьте переопределение **после** `...media(...)` в объекте проекта:

```ts
...media('byd', [/* существующие подписи */]),
cover: 'media/projects/byd/new-cover.webp',
hero: 'media/projects/byd/new-hero.webp',
```

Галерея задаётся массивом. Можно заменить весь массив после `...media(...)`:

```ts
gallery: [
  { src: 'media/projects/byd/launch.webp', caption: 'Song Plus Champion launch' },
  { src: 'media/projects/byd/outdoor.webp', caption: 'Outdoor campaign in Tashkent' },
],
```

Меняйте подписи вместе с изображениями. Подпись используется и как альтернативный текст для доступности. Не представляйте реконструированные или сгенерированные изображения как фотографии реального проекта: отмечайте их как mockup / reconstruction / concept.

## 6. Как добавить видео

1. Экспортируйте MP4 с H.264 (лучше всего поддерживается браузерами) или WebM с поддерживаемым кодеком.
2. Скопируйте файл в `public/media/projects/byd/campaign-video.mp4`.
3. Добавьте постер `poster.webp` в ту же папку.
4. В объекте BYD в `src/data/content.ts` добавьте:

```ts
video: 'media/projects/byd/campaign-video.mp4',
poster: 'media/projects/byd/poster.webp',
```

5. Откройте кейс, прокрутите к фильму и нажмите Play. Компонент использует нативные элементы управления и отдельную кнопку Play/Pause. Видео не запускается автоматически и изначально muted; зритель сам управляет звуком.
6. Для отключения удалите свойство `video` или задайте `video: undefined`. Вместо плеера появится постер (или hero) с прозрачной подписью о будущем оригинальном видео.

`Video` расположен в `src/components/Media.tsx`, принимает `src`, `poster`, `title`, `loop`. Файл подключается только при приближении блока к viewport, `preload="none"`; используется `playsInline` для телефонов. При уходе из viewport воспроизведение ставится на паузу. При включении reduced motion во время просмотра плеер также ставится на паузу. Отсутствующий или повреждённый файл приводит к визуальному fallback. Не добавляйте autoplay со звуком.

## 7. Как менять тексты

Откройте **`src/data/content.ts`**. Не нужно разбирать JSX для обычного редактирования.

| Что менять | Где |
|---|---|
| Строки hero | `site.headline` — массив из трёх строк |
| Короткое позиционирование | `site.intro`, `site.description` |
| Основная биография | `site.about` |
| Email, телефон, Telegram | `site.email`, `phone`, `phoneLabel`, `telegram` |
| Названия ссылок меню | `site.nav` |
| История работы | `experience` |
| Компетенции | `expertise` — пары заголовок / описание |
| Название и бренд кейса | `projects[].name`, `brand` |
| Краткий текст и hero кейса | `headline`, `summary` |
| Цель | `objective` |
| Обязанности | `responsibilities` — массив строк |
| Подход и реализация | `execution` — массив `{ title, text }` |
| Результаты | `outcomes` — массив `{ value, label }` |
| Ограничения и источник результатов | `note` |
| Год / период | `period`; пустая строка означает отсутствие проверенного периода |

Например:

```ts
email: 'new-address@example.com',
phone: '+998901234567',
phoneLabel: '+998 (90) 123-45-67',
```

Телефон для `tel:` пишется без пробелов. `headline` лучше оставить из трёх коротких строк: длинный текст потребует корректировки размеров на мобильном. После правок сохраните файл: Vite обновит страницу. Синтаксическая ошибка обычно означает пропущенную запятую или кавычку; терминал и `npm run build` покажут место.

Повторяемые разделы редактируются в данных. Отдельные художественные фразы, заголовки секций и подписи интерфейса находятся в `src/App.tsx`: `Home`, `About`, `Contact`, `CaseStudy`. Если хотите изменить текст `LET’S MAKE SOMETHING MATTER`, найдите `contact-heading` поиском VS Code (**Ctrl+Shift+F**). Шрифт, цвета, отступы и адаптивность меняются в `src/styles.css`.

Не добавляйте непроверенные бюджеты, продажи, ROAS, охваты или награды. У Milliy цифры относятся к продукту и зафиксированы в предоставленном портфолио. Они не являются текущими данными магазинов приложений. Указанные периоды работы взяты из резюме; год исполнения отдельного кейса не выводится из периода агентской работы автоматически.

## 8. Как добавить седьмой проект

1. Создайте `public/media/projects/new-project/`.
2. Добавьте `cover.webp`, `hero.webp`, `gallery-01.webp`.
3. В конец массива `projects` добавьте объект (все обязательные поля показаны):

```ts
{
  slug: 'new-project',
  name: 'NEW PROJECT',
  brand: 'Verified client name',
  category: 'Integrated campaign',
  period: '',
  role: 'Verified project role',
  color: '#B69AFF',
  headline: 'A clear project headline.',
  summary: 'A concise, factual introduction.',
  objective: 'The documented project objective.',
  responsibilities: ['Managed the documented scope of delivery.'],
  execution: [
    { title: 'From brief to delivery.', text: 'Explain the verified approach and execution.' },
  ],
  outcomes: [
    { value: 'Delivered', label: 'A verified qualitative outcome.' },
  ],
  note: 'State the source and any limitations of the outcomes.',
  ...media('new-project', ['A precise description of the gallery image']),
},
```

4. Маршрут `/#/work/new-project` и переход Next Project создаются автоматически. Порядок определяется массивом.
5. В `src/styles.css` при желании задайте отдельную композицию для `.slot-6`. По умолчанию на desktop она займёт половину сетки, на mobile — всю ширину.
6. Обновите счётчик `06` в `Header` и `ProjectCard` в `src/App.tsx`, фразу `Six projects` и подписи, если число кейсов изменилось.
7. Обновите тестовый массив `projects` в `tests/portfolio.spec.ts`, README и медиачеклист.
8. Выполните `npm run build`, откройте прямую ссылку, обновите её и проверьте Next Project.

В примере текст и бренд намеренно условные: замените их фактами своего реального проекта перед публикацией.

## 9. Как добавить или обновить CV

PDF уже добавлен: `public/documents/artem-yugay-cv.pdf` — предоставленный русскоязычный документ. Для обновления просто замените файл с тем же именем. Если имя другое, измените `site.cv` в `src/data/content.ts`:

```ts
cv: 'documents/my-new-cv.pdf',
```

Ссылка Download CV на About использует это значение. Обновите подпись `PDF · RUSSIAN`, если язык поменялся. Исходное английское портфолио сохранено рядом как `artem-yugay-portfolio.pdf`; его путь — `site.portfolio`. Перед публикацией проверьте, что все контактные и личные данные в PDF вы действительно хотите сделать общедоступными.

## 10. Публикация на GitHub Pages

### Базовый путь

По умолчанию `vite.config.ts` использует `base: './'`. Это относительные пути: одна сборка поддерживает и `username.github.io/repository-name/`, и `username.github.io/`. Пути медиа строятся через `import.meta.env.BASE_URL`. Имя владельца и репозитория не зашито в код.

При необходимости можно явно задать `VITE_BASE_PATH=/repository-name/` для проекта или `/` для корневого сайта. Это необязательно для текущего HashRouter. На Windows задайте переменную средствами своей оболочки, либо временно измените `base` в конфигурации. **Не** указывайте абсолютный путь вашей локальной папки.

### Пошаговая публикация

1. Создайте аккаунт на https://github.com/ и подтвердите email.
2. Нажмите **New repository**. Для бесплатной публичной публикации создайте публичный репозиторий. Имя может быть любым, например `portfolio`. Для корневого сайта имя должно быть точно `YOUR_USERNAME.github.io`.
3. Если используете уже подготовленный репозиторий, не создавайте новый и не меняйте origin без необходимости.
4. Если папка ещё не является Git-репозиторием:

```bash
git init
git branch -M main
git add .
git commit -m "Build Artem Yugay portfolio"
git remote add origin https://github.com/YOUR_USERNAME/YOUR_REPOSITORY.git
git push -u origin main
```

Если Git уже настроен, достаточно `git add .`, `git commit` и отправки существующей ветки. Команды инициализации и добавления origin повторять не надо. GitHub не принимает пароль аккаунта для HTTPS Git: используйте вход через поддерживаемый менеджер учётных данных или GitHub Desktop. Не записывайте токены в код.

5. Убедитесь, что файлы находятся в корне репозитория, включая `.github/workflows/deploy.yml`, `package.json` и `package-lock.json`. `node_modules` и `dist` загружать не надо.
6. В GitHub откройте **Settings → Pages → Build and deployment → Source → GitHub Actions**.
7. Workflow запускается при push в `main` либо вручную через **Actions → Deploy portfolio to GitHub Pages → Run workflow**. Если основная ветка называется иначе, измените `branches: [main]` в workflow на фактическое имя.
8. Откройте вкладку **Actions**, дождитесь зелёных шагов `build` и `deploy`. Установка выполняется через `npm ci`, Node.js 22, затем TypeScript и Vite build. Workflow использует минимальные разрешения для публикации Pages.
9. Найдите опубликованный URL в **Settings → Pages** или в результате job `deploy`.
10. Откройте сайт, перейдите в каждый кейс, обновите вкладку, скачайте CV, проверьте контакты и мобильное меню. Для кейса ссылка должна включать `#/work/...`.

Публикация не выполняется автоматически из этого чата: код и workflow подготовлены локально; отправка в GitHub и фактический статус Pages требуют отдельного выполнения. Не считайте сайт опубликованным только по успешной локальной сборке.

### Метаданные и социальная обложка

`index.html` содержит description, Open Graph, favicon. Заголовок вкладки меняется для About и каждого кейса. Для реального домена добавьте `og:url` и абсолютный URL изображения. Соцсети часто не поддерживают SVG: готовый `public/social-cover.jpg` (1200×630) уже добавлен. Замените `og:image` на **полный HTTPS-адрес JPG**. При изменении исходного SVG повторно экспортируйте JPG. Фрагменты HashRouter обычно не индексируются как независимые HTML-страницы; для отдельного SEO каждого кейса в будущем нужна статическая генерация или prerender. Не подставляйте вымышленный canonical URL до выбора домена.

## 11. Как обновлять опубликованный сайт

1. Измените текст или замените медиа локально.
2. Выполните `npm run build` и `npm run preview`.
3. Проверьте `git status`: не добавляйте лишние файлы и секреты.
4. Сохраните изменения:

```bash
git add .
git commit -m "Update project media and copy"
git push
```

5. Откройте Actions и дождитесь успешного запуска. Если ваш push не в `main`, сделайте merge в настроенную ветку обычным процессом проекта.
6. Обновите сайт с очисткой кеша (**Ctrl+Shift+R**). При необходимости проверьте актуальный commit в Actions.

Альтернатива для новичка — GitHub Desktop: просмотреть изменённые файлы, написать описание, нажать Commit, затем Push origin. Не загружайте вручную `node_modules`.

## 12. Проверки

Сборка:

```bash
npm ci
npm run build
```

Браузерные тесты требуют Chromium. В облачной среде он находится в `/usr/bin/chromium`. Для своей машины установите Chromium через Playwright:

```bash
npx playwright install chromium
```

Затем укажите фактический путь к браузеру через `CHROMIUM_PATH` либо уберите `executablePath` из `playwright.config.ts`, чтобы Playwright использовал установленную им версию. Пример для Linux:

```bash
CHROMIUM_PATH=/usr/bin/chromium npm test
```

Тесты запускают production preview в подпапке `/portfolio/`, проверяют desktop/mobile, шесть прямых маршрутов и refresh, переходы, реальные изображения, отсутствие overflow, CV, контакты, клавиатуру, reduced motion и резервные состояния. Скриншоты и trace при ошибке — в `test-results/`. Перед тестами сделайте новую сборку. Lighthouse можно запустить в Chrome DevTools → Lighthouse; числовой балл не гарантируется и зависит от устройства, сети и финальных медиа.

## 13. Частые ошибки

| Симптом | Что проверить |
|---|---|
| `npm not found` | Установлен ли Node.js; перезапустите терминал; проверьте `node --version` и PATH установщика |
| `Cannot find module` / нет зависимостей | Находитесь ли в папке с `package.json`; выполните `npm ci` |
| Порт занят | Остановите свой предыдущий процесс Ctrl+C или откройте порт, выданный Vite |
| Изображение не загрузилось | Файл действительно существует; регистр букв совпадает; нет `public/` в пути; формат настоящий; обновлён массив галереи |
| Вместо фото абстрактная композиция | Это fallback: браузер не получил файл; проверьте Network и путь в `content.ts` |
| Пустая страница после деплоя | Откройте Console и Network; проверьте base и что Pages публикует artifact из `dist`, а не исходный `index.html` |
| Ошибка base path | Используйте стандартное `./` или точное `/repository-name/`; не вставляйте URL GitHub-репозитория |
| Прямая ссылка даёт 404 | Для маршрута нужен `/#/work/byd`, а не `/work/byd`; не удаляйте HashRouter |
| Actions не запускается | Push должен быть в ветку `main`, либо измените workflow; проверьте, включены ли Actions |
| Actions build падает | Откройте красный шаг, исправьте TypeScript/установку; не удаляйте lockfile без причины |
| Actions deploy падает | Pages → Source: GitHub Actions; проверьте разрешения и доступность Pages для репозитория |
| Видео не играет | H.264 MP4, корректный путь, файл загружен в репозиторий, нет слишком тяжёлого файла; нажмите Play вручную |
| Анимаций нет | Проверьте системное «Уменьшить движение»; это ожидаемое поведение. Затем Console и импорт `motion.ts` |
| Мобильный текст выходит за экран | Укоротите заголовок либо скорректируйте mobile-правила в `styles.css`; проверьте минимум 375 px |
| Тесты не находят браузер | Установите Playwright Chromium или задайте `CHROMIUM_PATH`; на Windows не используйте Linux-путь |
| CV скачивает старую версию | Замените PDF, сделайте build/push и дождитесь нового deploy; обновите кеш браузера |

## 14. Собственный домен — необязательно

После первой успешной публикации можно купить домен у выбранного регистратора. В **Settings → Pages → Custom domain** укажите доменное имя. Настройте DNS по актуальной официальной инструкции https://docs.github.com/pages/configuring-a-custom-domain-for-your-github-pages-site — для поддомена обычно CNAME на `YOUR_USERNAME.github.io`, без имени репозитория. Для apex-домена используйте текущие A/AAAA-записи GitHub из документации. Дождитесь DNS и сертификата, включите Enforce HTTPS.

Для workflow со статическим artifact сохраните файл `public/CNAME` с одной строкой вашего домена: Vite скопирует его в `dist`. Не добавляйте фиктивный CNAME заранее. При необходимости задайте base `/`, обновите абсолютные Open Graph URL. HashRouter продолжит работать.

## 16. Английская и русская версии — EN | RU

В верхней панели есть переключатель **EN | RU**. Он всегда виден, в том числе на телефоне при закрытом меню. По умолчанию сайт открывается на английском. Выбранный язык сохраняется в браузере (`localStorage`, ключ `artem-portfolio-language`) и используется при переходах и обновлении страницы. При недоступном хранилище переключение продолжает работать в текущей вкладке. Маршрут кейса при переключении не меняется.

Переведены главная, шесть кейсов, About, опыт работы, подписи галерей, заглушки, кнопки, меню, альтернативные тексты изображений, заголовки вкладок и метаописания. Названия международных брендов и контактные адреса сохраняются. Текст внутри исходных фото, скриншотов и PDF не меняется: CV уже на русском, английское PDF-портфолио остаётся исходным документом. Для перевода встроенного текста изображения нужно заменить сам файл.

Где редактировать:

| Файл | Назначение |
|---|---|
| `src/data/content.ts` | Английские тексты, исходные пути медиа и общие контакты |
| `src/data/content.ru.ts` | Русские тексты, опыт работы, кейсы, результаты и подписи галерей |
| `src/data/messages.ts` | Соответствие английских и русских надписей интерфейса |
| `src/i18n.tsx` | Выбор языка, сохранение, `lang` документа и метаданные |

Пути медиа наследуются из английской конфигурации: заменять фотографию дважды не требуется. Контакты тоже общие. Если добавляете седьмой проект, обязательно добавьте запись с тем же `slug` в `translations` файла `content.ru.ts` и русские подписи для каждого изображения галереи. Все поля переводимой записи проверяет TypeScript. Не удаляйте английский ключ из `messages.ts`, если его использует `t(...)` в компоненте; меняйте русское значение либо обновляйте ключ и все обращения вместе.

Кириллические заголовки используют локальный Oswald, основной текст — Manrope, метаданные — IBM Plex Mono. Шрифты включены в сборку и не требуют внешнего запроса. Для русской версии предусмотрены отдельные размеры заголовков и мобильные правила в конце `styles.css`.

Браузерные тесты дополнены проверками EN/RU: сохранение после reload, переключение внутри кейса, русская карьерная история и все шесть кейсов, скачивание CV, обратный переход на английский, ширины 360 и 768 пикселей. Запуск: `npm run build`, затем `npm test`.
